# pr-precheck: rubric-driven PR grading

## The question

Answer exactly one question:

Is this pull request ready to submit?

A PR package consists of the issue, the accepted plan, the branch diff, the draft pull request title and description, and the supporting test evidence. Read the package against the issue and the plan it claims to implement. Do not grade anything outside that package.

## Inputs and modes
Live mode reads:

- the issue URL
- plan.md including deviation notes
- the branch diff generated by git diff main...HEAD
- the draft PR title and description in pr_draft.md
- the validation evidence in test_evidence.md
- repository guidance such as the PR template and CONTRIBUTING.md

House-chain students read the house plan and house repro package in place of their own plan and repro materials.

Eval mode reads only the provided package bundle. Nothing is fetched and every check is executed using only the bundle contents.

## The scope seam (live mode only)
Read scope.md before grading.

Refuse to grade work outside the repository named in scope.md.

If the Repo line still contains the shipped placeholder, stop without grading and instruct the student to fill the Repo line in scope.md.

Never infer or guess the repository.

Eval mode ignores scope.md entirely.

## The voice seam (live mode only)

Read voice-guide.md before evaluating the draft PR title and
description.

Report any violated voice-guide rules in the written summary.

Voice-guide violations do not change the verdict unless a rubric check explicitly evaluates them.

Eval mode ignores voice-guide.md entirely.

## Component reads
Use rubric.md to determine checks and verdict rules.

Use references/evidence-guide.md to locate evidence.

Execute procedure.md exactly as written.

If procedure.md is silent on a required action, report the gap and do not invent a replacement step.

If rubric.md or procedure.md contains no authored content, refuse to grade and explain that the tool is incomplete.

## Verdict and output

The verdict space is binary:

- accept = ready to submit
- reject = hold

End the response with the required JSON block. The JSON block must be
valid, must be last, and nothing may appear after it.

```json
{
  "item": "<PR URL or bundle id>",
  "checks": [
    {"name": "<check name>", "grade": "pass|fail|unclear",
     "evidence": "<one line: the fact or quote that decided it>"}
  ],
  "verdict": "accept|reject"
}
```

## Grading discipline

Evidence first. Do not grade a check without naming the fact or quote that determined it.

Grade the artifact, not its polish.

Apply the rubric exactly as written.

Follow procedure.md exactly as written.

When the rubric is silent, treat unclear as fail.
